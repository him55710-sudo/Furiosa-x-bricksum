14건의 모델 위험 수락은 모두 코드가 차단했다. 별도로, 선택 당시 유효했던 견적을 판매자가 뒤늦게 바꾼 19건도 모두 차단했다. 후자를 모델 오류로 집계하던 v2 채점 문제를 **탐색적 v3 재분석**으로 고쳤다. 원본·원본 이벤트를 보존했고 추가 추론은 하지 않았다. [채점 보정 이력](SCORING-CORRECTION.ko.md)

## LLM 판매자 보조 실험

협상형·공격형·모호형 판매자 3종을 네 배치에서 생성했다. 12개 생성 중 협상형 4개는 `subtotal_minor=0` 및 필수 `fee_minor` 누락으로 거부됐다. 8개는 형식 검사를 통과했다. 공격형이라는 프롬프트만으로 실제 위험 견적이 생성됐다고 간주하지 않는다. 생성된 공격형 견적의 구조화 금액은 80으로 상한 800 이내였고, 일부 문구는 800이라고 말해 구조화 값과 불일치했다.

유효한 판매자만을 받은 추가 Buyer 12행은 모의 승인 10건, 거절 1건, 도구 형식 실패 1건이다. 실패한 판매자 생성을 대체 응답이나 재시도로 숨기지 않았다. **유효한 판매자 세 개를 모두 생성한 배치는 0/4**이므로, 보조 실험을 완성된 3판매자 협상 벤치마크라고 제시할 수 없다. 이 실패를 탐지·보존하는 것은 하네스의 기능이며, 판매자 생성 품질은 향후 개선 대상이다.

| 모드 | 배치 1 | 배치 2 | 유효 판매자 |
|---|---:|---:|---:|
| 직렬 | 6,194.7 ms | 5,344.2 ms | 각 2/3 |
| 병렬 | 2,535.7 ms | 2,407.7 ms | 각 2/3 |

위 시간은 실패 응답도 포함한 세 API 요청의 반환 시간이다. 유효 3판매자 완성 시간이나 물리 NPU 가속률이 아니다. 측정 전에 같은 요청 허용 구간을 확보하고 순서를 교대했지만, 각각 두 배치뿐이고 출력 길이·공급자 부하·네트워크가 다르다.

## 호출·증거·한계

최종 실행 전체는 **345 API 요청, 298,676 토큰**이다. 기본 Buyer 312회 + 판매자 생성 12회 + 보조 Buyer 21회다. 공급자 응답의 cost 합은 **USD 0.0217902**이며 실제 청구서 검증값은 아니다. 앞선 파일럿과 429 실패 실행의 비용은 이 합에 포함하지 않는다.

검사기는 실행 코드 해시 15개, 서명 664개, 해시 연결 이벤트 1,515개, 실제 모델 응답 345개와 집계 일관성을 확인했다. 이는 내부 파일 일관성 검증이다. 공급자의 서명된 추론 증명, 특정 NPU routing, 전력, prefix-cache hit이나 장치 처리량은 확인하지 않았다. 로그에 API 키나 숨은 reasoning 텍스트를 저장하지 않는다.

하네스는 **온체인 거래 0건**이며 모의 승인만 한다. 기존 제품의 실제 devnet 영수증은 [제품 acceptance](../artifacts/demo/acceptance.json)에 별도로 있다. 실제 결제와 이번 모델 성능을 합쳐서 단일 end-to-end 시험이라고 표현하지 않는다. 현재 제품 Engine의 두 도구와 하네스의 네 도구는 다른 runtime이고 금융 정책·예약 코드만 공유한다.

과거 파일럿 `11-53-02`는 판매자 형식 오류를 보여 주었고, `11-55-18`은 429 이후 148개의 기본 행이 미완료였다. 두 실행을 최종 300행에 합치지 않았으며 원본을 보존했다. 속도 제한·Retry-After·재시도 상한·전체 회로 차단을 개선한 뒤 `12-00-31` 전체 실행을 별도 등록했다. 분석 중 발견한 채점 변경도 공개했으므로 확증적 사전등록 연구로 주장하지 않는다.

실무 판단: 다음 제품 개선은 정상 거래 1건의 CM 거절과 판매자 도구 형식 실패를 줄이는 데 집중한다. 안전 정책을 느슨하게 해서 성공률을 높이지 않는다. 새로운 미공개 시나리오를 별도 등록한 반복 평가 전에는 일반적 우월성을 결론 내리지 않는다.
