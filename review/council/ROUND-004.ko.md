## 기획 v3: 좁아진 문제, 새 아이디어와의 중요한 차이

심사역: 자료 1건·지급 1회·실행 2회라는 장면, Qwen의 자료 판단/해석 역할, 두 독립 위반·증빙 보존은 더 명확하다. 현재 구현과 신규 계획을 분리한 점이 적절하다.

VC: 공개 신고와 API 문서를 실고객/시장 크기로 승격하지 않고 SDK+DB가 충분한 경우를 반증으로 넣었다. 사용자 수요가 검증됐다고 닫지는 않는다.

구현 검증: 새 purchaseId 계약 latch와 결과 회수는 아직 계획이다. 기존 중복 paymentKey 테스트가 새 보장의 증거가 아님을 문서가 명시했다. x402 호환성·품질·판매자 회수 의존도도 인정하므로 반복 지적하지 않는다.

새 직접 사용자 선호는 ‘escrow 가능한 상품으로 좁히기 + Buyer/Seller 협상 근거 + 회사 감사’다. [비교표 002](IDEA-COMPARISON-002.ko.md)의 **EV-007 상품·납품 판정 경계 검증 하나**를 다음 후보로 제안한다. 판정권자 없이 schema/hash만 보고 자동으로 납품 품질이 보장된다는 source AI 설명은 보완한다. escrow 구현·유료 실험·추가 플랫폼 확장을 이번 감시에서 실행하지 않는다.

## 이전 대기 비교와 범위

비교001의 리서치 업무·예시 수치 구분·Qwen 후보와 모델 오류 구분·x402 역할 구분은 v3에 대부분 반영됐다. I-003은 C-E02 완료로 정리한다. 기존 7개를 그대로 재발송하지 않고 새 방향과 완료 결과만 합친다. queued coordinationNotice도 첫 적격 발송에 한 번만 합친다.

이번 snapshot의 큰 추가 목록에는 감시 경로 확장으로 처음 등록된 harness/learning/verification도 포함된다. 이것들을 이번 정정/기획 검토에서 전부 실행 검증한 것으로 주장하지 않는다. 해당 하위 시스템의 의미 있는 최신 결과는 다음 관련 완료 시 별도 검토하도록 evolution.json의 deferredEvidence에 남긴다. snapshot ack는 변경 감시 기준선이며 모든 파일의 품질 인증이 아니다.

기획 본문·제품 코드는 개발 세션 소유로 유지한다. 발송 여부와 정확한 marker·문구는 로컬 delivery.json, 아이디어 배치 처리와 전달 상태는 ideas.json을 따른다.
