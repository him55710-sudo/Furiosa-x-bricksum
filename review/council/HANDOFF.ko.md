# 기획 세션에 전달할 개선 요청

Control Memory의 심사역·VC 관점 1차 검토와 보완 기획을 같은 작업 폴더에 저장했습니다.

- 기획: `docs/HACKATHON-PLAN.ko.md`
- 근거와 판정: `review/council/ROUND-001.ko.md`, `review/council/findings.json`
- 원본: `review/vendor/gstack`의 Garry Tan gstack, commit `01593aa67c94780528e8f5121e47362502410ced`.

현재 진행 중인 작업을 보존하면서 다음 세 항목을 기획·구현에 반영해 주세요.

1. **C-J02:** 설계 추가보다 mandate→offer→정책 판정→결과→export를 같은 run ID로 연결하는 첫 흐름을 먼저 구현해 주세요. 정상 run 1개·독립 STOPPED 2개·성공 체인 receipt·독립 검증이 완료 기준입니다. 기존 안전 요구는 유지합니다.
2. **C-V01:** 고객을 ‘업무 에이전트와 도구 예산을 함께 책임지는 개발 리드’라는 가설로 명시하고, 실제 API 크레딧 구매 빈도·현재 승인/영수증 방식·도입 행동을 검증할 과제로 남겨 주세요. 고객·가격·시장 규모를 만들어내지 말아 주세요.
3. **C-V02:** 기본 승인·통제·재검증 가치와 Control Memory 효율 가설을 분리해 발표해 주세요. 기존 B0/B1/CM 결과가 이득을 보이지 않으면 효율 우월성 문장을 철회하는 조건을 반영했습니다.

필수 gpt-oss-120b model_not_found는 기존 R1-01/C-J01 외부 의존성입니다. 운영사 상태 변화 없이 같은 요청을 반복하지 말고 독립 구현을 진행해 주세요. 리뷰 동의·문서 수정과 실제 검증 완료를 구분해 주세요.

이 검토 세션은 `review/council/`과 새 보완 기획만 관리합니다. 기존 아키텍처 및 제품 파일의 변경은 대상 세션에서 판단해 반영하고, 판정과 근거를 작업 파일에 남기면 다음 검토에서 읽겠습니다. 다른 대화로 다시 메시지를 보내라는 요청은 아닙니다.
