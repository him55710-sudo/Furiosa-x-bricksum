# 반복 검토 실행 지침

작업 폴더는 이 저장소의 루트다. 사용자가 승인한 대상과 주기는 delivery.json 및 자동화 설정에서 확인한다. 이 문서만으로 새로운 대상에게 발송할 권한은 생기지 않는다.

1. PERSONAS.ko.md, findings.json, delivery.json을 읽는다. `node scripts/council-snapshot.mjs`를 실행한다. 입력 변화가 없고 미처리 발송도 없으면 조용히 끝낸다. 새 반례를 채우기 위해 문제를 만들지 않는다.
2. 변경된 파일과 기존 Grok 리뷰·council 지적을 비교한다. 실제 데이터가 필요하면 해당 파일만 읽는다. 제품 코드·docs·실행 증거가 사실의 근거다. 비밀/환경 파일은 읽거나 메시지에 포함하지 않는다.
3. 심사역, YC식 VC, 구현 검증자 관점으로 순서대로 판단한다. 판정은 실제 증거에 따라 하고, 이미 해결된 지적은 근거 없이는 다시 열지 않는다.
4. review/council 안에 새 round와 findings를 기록한다. 필요한 보완은 docs/HACKATHON-PLAN.ko.md에 반영한다. 다른 세션이 관리 중인 아키텍처·제품 파일을 동시에 덮어쓰지 않는다.
5. 새 P0/P1, 우선순위 변화, 검증 완료처럼 의미 있는 변화만 최대 3개로 묶어 승인된 기획 세션에 send_message_to_thread로 전달한다. ID, 근거, 최소 수정, 완료 조건, 변경 파일을 명시한다. 일반적인 상태 요약, 같은 외부 차단, P2 문장 다듬기만으로는 메시지를 보내지 않는다.
6. 발송 결과를 확인한 뒤 delivery.json에 timestamp, fingerprint, finding IDs, targetThreadId를 기록한다. 발송 결과가 모호하면 대상의 최근 메시지에서 확인하고 중복 발송하지 않는다. 중요한 변화가 없으면 발송 없이 검토만 기록한다.
7. `node scripts/council-snapshot.mjs --ack <검토한 fingerprint>`로 검토 기준을 저장한다. 해시가 바뀌어 거부되면 새 파일을 읽고 중요한 변화를 놓치지 않게 보완한다. 실패를 검토 완료로 처리하지 않는다.

모델 가용성은 새 운영사 정보나 실제 증거가 생겼을 때만 재확인한다. 주기마다 유료 추론·체인 전송·Grok 호출을 실행하지 않는다. 새로운 외부 메시지·결제·배포·공개 게시를 이 검토 자동화에 포함하지 않는다.

사용자에게는 의미 있는 변경·완료·실행 실패·결정이 필요한 경우에만 알린다. 입력·상태가 같으면 조용히 종료한다. 매회 확인했다는 알림을 남기지 않는다.
