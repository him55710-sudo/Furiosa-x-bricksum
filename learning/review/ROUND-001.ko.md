# Grok 학습 모듈 검토 1차

2026-09-28 · marker `GROK-LEARNING-R1` → 구현 후 `GROK-LEARNING-R2` 발송

대화: [GWDC 비판·검증 디렉터](https://grok.com/bot/b10ed257-50ea-4fad-9a33-466b2cfa1547). 사용자의 명시적 지시에 따라 기존 웹 봇에 설계·실험 요약을 전달했다. Grok는 로컬 코드를 읽거나 실행하지 않았고, 전달받은 요약을 검토했다. 아래는 응답의 자체 요약과 코드 대조 결과다.

## 지적과 판단

| Grok 지적 | 판단 | 실제 반영 |
|---|---|---|
| D1: 양이 많을수록 좋다는 선형 특성은 적정량 선호를 표현하지 못함 | 적용 범위 지적으로 채택. 가격도 함께 다른 예시만으로 수량 가중치가 반드시 0으로 간다고 단정할 수는 없음 | 적정량·환불 포화 합성 상황 추가. 사용자 목표량을 임의로 정해 기존 스키마를 교체하거나 범위 밖 값을 잘라 넣는 제안은 채택하지 않음 |
| D2: 취향 변경 뒤 과거 학습으로 나쁜 추천 가능 | 실제 drift regret 악화로 확인. 사후분포가 항상 좁아진다는 일반 주장은 기각 | 명시적 변경으로 새 epoch 시작, 기존 질문·승인·증거와 분리. drift의 현재 참 w에 대한 구간 포함률 추가 |
| D3: 정보이득 질문의 평균 차이만으로 우월/열등 결론 불가 | 채택. 기존 JSON의 분산·정상 구간 포함률은 이미 존재했음을 정정 | 사용자별 짝 bootstrap, 개선/동률/악화 수, w만의 정보이득, 새로운 seed의 별도 평가 |

범위 밖 상품 제외는 이미 코드와 서명 경계 테스트에 있었다. 기존 threshold 비선형 조건도 이미 있었다. 이 항목들은 새 결함이나 신규 구현으로 세지 않는다. 기존 active 실험은 12명이며 전체 합성 상황의 24명과 구분한다.

## 구현

- `model.mjs`: w를 조건으로 β를 적분한 정보이득, epoch와 시작 시각이 맞지 않는 증거 거부.
- `profile.mjs`: `beginPreferenceEpoch`, 과거 학습 보존·진행 질문 무효화·이전 epoch 정책 거부. 질문 목표 필수 지정.
- `statistics.mjs`: 사용자 ID로 짝지은 percentile bootstrap. 개별 응답을 독립 사용자로 세지 않음.
- `simulate.mjs`: 7개 상황, 기존/신규 active cohort, 명시 리셋 이후의 재학습.
- 추가 테스트: β만 식별하는 질문, 정보이득 관계, 명시 변경 경계, bootstrap 짝 일치.

R2 전송 시점에 로컬 테스트 23개 통과. 이후 추가 검증은 [2차 기록](ROUND-002.ko.md)을 따른다.

## 수치 해석

정상 조건의 Bayesian−균등 regret 평균 차이는 -0.0197, 탐색적 bootstrap 구간 [-0.0361,-0.0033]이다. drift는 +0.0433 [0.0231,0.0641]로 반대 방향이다. 적정량·포화 상황은 구간에 0이 있어 개선이나 동등성을 확인했다고 말하지 않는다.

신규 seed의 질문 12회에서도 joint 정보이득과 w 정보이득의 임의 질문 대비 구간이 모두 0을 포함한다. w-only가 점추정에서 낮다는 이유로 실사용 기본값으로 승격하지 않았다. [확장 계획](EXPERIMENT-V2.ko.md)은 기존 결과를 본 뒤 세운 탐색적 계획임을 명시했다.

Bootstrap 방법의 원 논문: B. Efron, 1979, [Bootstrap Methods: Another Look at the Jackknife](https://doi.org/10.1214/aos/1176344552). 사용자 단위 짝 비교·2,000회·이번 endpoint 선택은 우리의 분석 설계이며 이 논문이 이 프로젝트의 표본 수나 성공 기준을 정해 준 것은 아니다.
