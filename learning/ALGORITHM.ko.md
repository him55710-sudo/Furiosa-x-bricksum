# 어떤 증거가 어떤 상태를 얼마나 바꾸는가

이 문서는 연구에서 가져온 원리와 이번 프로토타입에서 선택한 설계를 구분한다. 상품 구매에 대한 검증된 최적 파라미터가 논문에 있다는 뜻은 아니다.

## 1. 상태와 입력의 경계

선호 상태의 범위는 `(ownerId, purpose, category, featureSchema)`이고, 현재 학습 세대는 `preferenceEpochId`로 구분한다. 호텔과 API 크레딧의 가중치를 섞지 않는다. 저장값은 설정·증거·철회 기록·선택적 상위 분류 스냅샷이다. 사후분포를 외부 JSON 숫자로 신뢰하지 않고 저장된 사건을 다시 계산해 복원한다. 한 epoch 안에서는 정적 선호를 가정한다.

| 사건 | 선호 변화 | 통제 변화 |
|---|---|---|
| 발급된 비교 질문에 소유자가 A 또는 B로 응답 | 관측 1개에 대한 Bayes 업데이트 1회 | 없음 |
| 환불 후 소유자가 구체적 대안 A/B의 선호를 확인 | 위와 같은 관측 1개, 환불이라는 이유로 1.5배 하지 않음 | 없음 |
| 환불 기록만 있음, 반복 구매, 무응답, 두 상품 모두 거절 | 없음 | 없음 |
| LLM이 선호를 추측, 판매자가 사용자 취향을 주장 | 입력으로 허용하지 않음 | 없음 |
| 동일 queryId/evidenceId의 동일 응답 재전송 | 중복 적용 없음 | 없음 |
| 동일 질문에 서로 다른 응답 재전송 | 충돌 오류, 상태 보존 | 없음 |
| 사용자가 기존 응답 철회 | 해당 관측을 제외하고 원래 사전분포부터 재계산 | 없음 |
| 소유자가 취향 변경을 명시 | 과거 스냅샷 보존, 부모 전이 없이 원래 대칭 사전분포로 새 epoch 시작 | 없음, 이전 epoch의 제안 승인은 재사용 불가 |
| 유효한 견적의 수수료가 승인 한도 초과 원인 | 없음 | 승인된 범위의 최종 총액 견적 요구 추가 |

단순 거절로는 어느 특성이 원인인지 알 수 없다. 거절 이유를 선택 가능한 대안과 함께 확인한 후 새 비교 사건으로 만든다. 자유 텍스트를 LLM이 해석해서 증거로 확정하는 경로는 제공하지 않는다.

## 2. 상품을 같은 단위로 표현

API 크레딧용 `api-credit-features-v1`은 다음 세 효용 특성을 쓴다.

```text
저렴함   = 1 - totalMinor / 4000
환불성   = refundHours / 168
수량     = quantity / 200
```

4000 minor units는 데모 TestCredit 40.00, 168시간은 7일이다. 모두 **데모의 범위 정의**이며 연구로 증명된 사용자 취향이 아니다. 범위를 넘거나 형식이 잘못되면 학습 순위에서 제외하고 사람이 판단한다. 0~1로 억지로 잘라 넣지 않는다. 후보군마다 최소·최대로 재정규화하지 않으므로 판매자가 무관한 비싼 상품을 추가해도 기존 특성이 변하지 않는다.

가격은 모든 수수료를 포함한 서명된 `total`이다. `checkOffer`가 서명·허용 판매자·목적·규격·기한·예산을 먼저 검사한다. 최소 수량·최소 환불시간은 하드 정책이고, 이를 만족한 뒤 더 높은 값을 선호하는 정도만 학습한다.

호텔은 거리·취소·가격 등 별도 특성과 고정 기준을 명시한 새로운 스키마가 필요하다. “수량은 많을수록 좋다” 같은 단조성이나 선형성이 맞지 않는 상품에는 현재 스키마를 그대로 쓰면 안 된다.

## 3. 가중치 하나 대신 가능한 가중치들의 확률

후보의 특성 벡터를 φ(x), 선호 가중치를 w라고 한다.

```text
U(x; w) = Σⱼ wⱼ φⱼ(x)
wⱼ ≥ 0, Σⱼ wⱼ = 1
θ = (w, β)
```

`w`는 2~4차원 단체(simplex)를 정수 격자로 나눈 후보다. 세 특성·20분할이면 가능한 w가 231개다. β가 3개이면 총 693개의 가설이 있다. 기본 예제는 모든 가설에 같은 사전 확률을 준다. 균등 사전분포도 설계 가정이며 객관적인 “무지”를 완전히 표현하는 것은 아니다.

β는 선택의 일관성/효용 차이에 대한 민감도다. 고정된 단위와 `Σw=1`로 스케일을 정의하고 β도 함께 추론한다. 예제는 β ∈ {1,2,4}, 비교 실험은 개발 데이터의 검증 손실로 후보 집합을 선택한다. 실제 사용자 데이터가 없으므로 이 값의 실사용 타당성을 주장하지 않는다.

## 4. 얼마나 업데이트하는가

APReL의 선형 softmax는 두 후보에서 Bradley–Terry 형태의 logistic 확률과 같다. 여기에 실수 응답을 나타내는 ε를 추가했다. ε는 이번 구현의 확장이다. [APReL 원 소스](https://github.com/Stanford-ILIAD/APReL/blob/13a1e7f7d93899682a414ce7812f4749dfcbf317/aprel/learning/user_models.py).

```text
Δφ = φ(A) - φ(B)
σ(z) = 1 / (1 + exp(-z))
P(A 선택 | θ) = ε/2 + (1-ε) σ(β wᵀΔφ)

Lₜ(θ) = P(A|θ)       if A 선택
       = 1 - P(A|θ)   if B 선택

pₜ(θ) = pₜ₋₁(θ) Lₜ(θ) / Σθ′ pₜ₋₁(θ′) Lₜ(θ′)
표시 가중치 = E[w | 확인된 응답들]
```

즉 두 가설의 사후 오즈는 `기존 오즈 × 관측의 우도비`다. 사전에 정한 `+0.1`만큼 움직이는 방식이 아니다. 어떤 선택인지, 서로 얼마나 다른 상품인지, 기존 증거가 무엇인지에 따라 변화량이 달라진다. 여러 특성이 함께 변하면 “환불이 원인이었다”고 확정하지 않는다.

손으로 검산할 수 있는 예:

```text
특성 두 개, w ∈ {(0,1), (0.5,0.5), (1,0)}, 사전확률 각각 1/3
A=(1,0), B=(0,1), β=ln(3), ε=0
A 선택 확률 = (1/4, 1/2, 3/4)
사용자가 A 선택
사후확률 = (1/6, 1/3, 1/2)
첫 특성의 평균 가중치: 1/2 → 2/3
```

이 계산은 테스트로 검증한다. 한 번의 선택이 항상 아주 작은 변화라는 보장은 없다. 높은 β는 더 강한 관측이 되므로 β 범위·ε를 실제 반복 응답의 일관성 자료로 정해야 한다. 동일 응답을 복제해 증거 수를 늘릴 수 없게 식별자를 검사한다. 다만 서로 다른 질문의 답변이 통계적으로 독립이라는 가정은 여전히 남는다. 같은 결정을 이름만 바꿔 다시 수집하는 것은 서버에서 막아야 한다.

모든 누적 확률은 로그 공간에서 계산한다. 미세한 가설 확률을 0으로 영구 제거하지 않아 장기간 반대 증거가 들어와도 복구할 수 있다. 유한 격자 안에서는 열거한 가설의 Bayes 업데이트를 정확히 계산하지만, 연속 가중치 공간의 정확한 사후분포라고 부르지는 않는다.

## 5. 신뢰도와 질문 여부

하나의 `confidence=0.82`를 반환하지 않는다.

| 출력 | 뜻 | 뜻하지 않는 것 |
|---|---|---|
| `credible95` | 각 특성 가중치의 2.5~97.5% 사후 분위수 | 실세계 정답률 95%, 모든 특성을 동시에 덮는 구간 |
| `predict(A,B)` | 모형이 예측한 A 선택 확률 | 결제 안전 확률 |
| `expectedRegret` | 같은 후보 중 실제 취향으로 더 좋은 후보와의 예상 효용 차이 | 금전 손실 |
| `probabilityRegretExceedsTolerance` | 정해진 효용 차이를 넘을 사후 확률 | 실제 사용자에서 보정된 오류율 |
| `probabilityBestWithSplitTies` | 가설별 최상 후보 확률, 동률은 나누어 배분 | 최고의 실제 상품임을 보장 |

모형이 틀렸을 가능성은 이 구간만으로 다 표현되지 않는다. 특성이 빠졌거나 취향이 바뀌면 구간이 좁아도 틀릴 수 있다. [보상 오인 연구](https://arxiv.org/abs/2204.06601v4)를 근거로 비선형·상관 특성·노이즈·취향 변화 실험을 포함했다.

질문 전략은 세 가지이며 `issueQuery` 호출 시 반드시 목표를 명시한다.

```text
정보이득 = H(Eθ[P(A|θ)]) - Eθ[H(P(A|θ))]
w 정보이득 = H(P(A)) - Σw p(w) H(Σβ p(β|w)P(A|w,β))
한 단계 질문가치 = 현재 최소 기대 후회 - 답변 후 최소 기대 후회의 기댓값
```

첫 수식은 불확실한 모형을 더 잘 구별하는 질문을 찾는다. [BALD](https://arxiv.org/abs/1112.5745v1)·APReL의 정보이득과 연결된다. β만 더 잘 알게 하는 질문도 선택할 수 있어, 현재 후보를 잘 고르는 데 항상 최선은 아니다. 두 번째는 현재 사후분포에서 β를 w에 조건부로 적분해 가중치에 관한 정보만 센다. 세 번째는 현재 후보 집합의 선택 손실 감소를 직접 계산한 이번 구현의 결정 이론적 설계다. APReL의 `regret` 함수와 같은 알고리즘이라고 주장하지 않는다.

`decide()`는 세 번째 질문가치가 사용자가 정한 질문 비용보다 큰지 비교한다. `READY_TO_PROPOSE`는 현재 epoch가 일치하는 사전 승인된 기대 후회·꼬리위험 기준, 별도 사용 동의, 해당 범위의 실제 검증 상태가 모두 충족될 때만 반환한다. **어떤 반환값도 결제 승인이 아니다.** 기준이 없으면 오류이고, 데모의 검증 상태는 항상 `synthetic_only`다. 비용 0.005나 위험 0.05는 효용 단위의 예시이지 학술적으로 최적인 임계값이 아니다.

## 6. 상품군 사이의 제한적 이전

명시적 취향 변경에는 `beginPreferenceEpoch`를 사용한다. 부모를 물려받지 않는 새 학습 세대를 만들고, 이전 질문의 늦은 응답과 이전 epoch의 정책을 거부한다. SQLite `EpochAuthority`가 현재 epoch와 단조 순번을 모델 저장본과 분리해서 보관한다. 저장소가 연결되지 않은 실험 profile은 `READY_TO_PROPOSE`가 될 수 없다. 자동 변화 탐지·시간 감쇠나 새 검증 상태의 자동 승격은 없다.

상위 분류의 저장된 사후분포를 선택적으로 가져올 수 있다. 조건은 같은 사용자·목적·특성 스키마이고, 자식 분류 경로가 부모 아래에 있어야 한다. 부모 → 자식의 방향으로만 반영하며, 부모 스냅샷을 고정한다.

```text
K(w_child | w_parent) ∝ exp(-κ ||w_child - w_parent||²)
p₀(w_child) = Σparent p(w_parent | parent evidence) K(w_child | w_parent)
```

K는 **각 부모 가설별로** 자식 격자에 대해 정규화한다. κ=0이면 자식의 균등 사전분포로 돌아간다. β는 자식에서 다시 균등하게 시작한다. 부모 증거를 자식의 새 증거로 다시 넣으면 오류다. 부모 데이터가 철회·수정되면 이를 물려받은 자식을 새 스냅샷으로 재구축해야 한다.

이는 이번 프로토타입의 조건부 혼합 사전분포이며, 논문에서 그대로 가져온 완전한 공동 계층 모형이 아니다. κ는 기본 자동 활성화 값이 없다. 같은 특성 의미를 가진 여러 하위 상품군의 실제 검증 데이터로 설정해야 한다. 호텔 평점 가중치를 API 수량으로 옮기는 기능은 없다.

## 7. 통제는 숫자 취향 점수가 아니다

`deriveFeeControl`은 실제 `checkOffer`가 서명 검증 이후 예산 실패를 반환했는지 확인한다. 이어서 다음 조건을 모두 검사한다.

```text
cap = min(perTxCap, totalCap - spent - reserved)
fee > 0
subtotal ≤ cap < total
subtotal + fee = total
autoHarden == true
```

이때만 동일 사용자·목적·판매자의 다음 협상 전에 최종 총액을 요구하는 통제를 추가한다. 기본 가격부터 이미 한도를 넘은 경우를 수수료 문제로 오인하지 않는다. 기존 통제 집합에 규칙을 추가할 뿐 예산·기한·허용 판매자를 변경하거나 차단 판매자를 임의로 늘리지 않는다. 견적을 고친 판매자는 여전히 기존 정책 아래서 거래 가능하다.

모든 기존 통제는 보존되고 동일 통제는 중복 생성되지 않는다. 이 별도 연구 모듈의 원인 검사는 현재 앱의 `src/policy.mjs`에 있는 `deriveControl`을 대체해서 배포한 것은 아니다. 연동 시 기존 3군 실험(B0/B1/CM) 규약도 유지해야 한다.
