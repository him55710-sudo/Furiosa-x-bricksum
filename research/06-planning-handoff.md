대조일: 2026-09-28. 기획 채팅 **「기획 GWDC 챌린지 시스템 아키텍처」**에서 저장한 아래 파일을 읽고 이 자료집을 맞췄다.

- [Kiln 연결 명세](../docs/KILN-INTEGRATION.ko.md)
- [심사용 데모 계획](../docs/DEMO-PLAN.ko.md)

이 문서는 기획 파일을 덮어쓰지 않는 연구 보충 자료다. 외부 연락이나 다른 채팅으로 메시지를 발송하지 않았다.

기획 세션의 완료 응답까지 확인했다. 완료 범위는 **설계와 연결 진단 코드**이며, 세션 보고상 진단은 `MISSING_KILN_API_KEY`에서 멈췄다. 제품 UI·테스트넷 결제는 구현할 단계로 남아 있다. 이 자료집은 그 완료된 설계안을 기준으로 정리했다.

## 현재 설계에 맞춘 권장 범위

소규모 팀의 API 크레딧 구매 위임을 대상으로 한다. 가상 판매자 3곳, 테스트넷 전용 TestCredit, Sepolia BudgetVault를 사용한다. 구매 후보 선택·제한된 협상은 Kiln, 승인·금액·판매자·기한·중지·검증은 코드와 계약이 담당한다. 이 내용은 현재 저장된 기획안이며 실제 구현 완료를 뜻하지 않는다.

첫 구현은 단일 worker와 SQLite의 원자적 쓰기 트랜잭션을 유지한다. 이 자료집의 PostgreSQL 행 잠금 설명은 동시 처리 확장 때 읽을 배경이다. 자료 조사 때문에 스택을 바꾸거나 벡터 DB·다중 판매자 LLM·복수 체인을 추가할 필요는 없다.

## 설계 결정 → 근거 → 실험

| 결정 | 관련 근거 | 우리 쪽에서 확인할 것 |
|---|---|---|
| 모델은 offer ID만 제안 | P01 AgentDojo, P02 CaMeL | 잘못된 ID·권한 확대 주입에도 실행 불가 |
| 원본 견적 재조회와 고정 총액 검사 | 신뢰 경계 설계 | 금액·주소 바꿔치기와 수수료 초과 차단 |
| 사용자 위임을 서명과 연결 | D11 EIP-712 | nonce, 만료, chain/contract domain, 재사용 차단 |
| 예산 예약과 중복 방지 | D13의 동시성 개념; 실제 스택은 SQLite | 예산 30에 20+20 경쟁, 동일 구매 재전송 |
| 컨트랙트에서 지출 검사 | D14 접근제어; 기획의 BudgetVault | 직접 호출·우회·중복 paymentKey도 차단 |
| 영수증 hash와 승인 자료 연결 | P05 BlockAudit, D12 JCS | 제3자 검증, 변조·누락 판정 |
| 통제 기억으로 조기 검사 | P02의 권한 분리에서 착안한 팀 제안 | 안전 기준 동일 조건에서 정상 성과·토큰 비교 |
| 입력·출력·호출 단계별 계측 | P03 에너지 연구, D05 usage | 실패·재시도 포함, 에너지 미관측 명시 |

논문이 이 제품 전체를 검증했다는 주장은 하지 않는다. Control Memory는 이 프로젝트의 적용 설계이며 신규성은 별도 조사 대상이다.

## 구현 전에 해결할 확인 항목

| 우선순위 | 확인 항목 | 현재 근거와 상태 | 완료 증거 |
|---|---|---|---|
| P0 | gpt-oss-120b 가용성 | 공개 모델 표는 coming soon. 기획 문서도 콘솔 비활성 관측을 보고함 | 인증된 모델 목록 + 실제 추론 응답 |
| P0 | 지정 호출의 NPU 라우팅 | 서비스 이름만으로 개별 요청의 물리 장치를 입증할 수 없음 | 대회 endpoint/model의 운영사 확인 또는 제공 계측 |
| P0 | 서버의 중지와 제출 경쟁 | 최종 재검사와 제출 시작 사이의 순서까지 명세 필요 | stop 먼저인 경우 새 제출 0, 먼저 제출된 것은 진행 중 표시 |
| P0 | 승인과 견적의 정확한 결합 | offer ID만 비교해서는 원본 변경을 잡지 못할 수 있음 | 서명된 offer hash·금액·수신자·기한 일치 |
| P1 | 수수료 책임 | 기획상 판매자 수수료 포함, gas는 운영자 지원 | UI·정책·원장·계약의 동일한 해석 |
| P1 | 실험 비교군 | 양쪽 모두 최종 안전 검사 유지 | 같은 fixture에서 조기 검사 유무만 변경한 로그 |
| P1 | 에너지 표현 | 하드웨어 계측 없음. 기획의 임의 계수는 시나리오일 뿐 | 실측 또는 출처·조건·범위를 밝힌 추정 |
| P1 | 이력 완전성 | 단일 hash 일치는 누락까지 증명하지 못함 | 체인 선행 이벤트 재구성·누락 시 INCOMPLETE |

이 자료 조사 세션에서는 API 키를 열어보거나 실제 추론·서명·체인 전송을 수행하지 않았다. 기획 세션의 연결 스크립트가 준비됐다는 사실과 그 스크립트의 성공 실행은 구별한다.

## 발표에서 수정하거나 피할 표현

| 과장되기 쉬운 표현 | 현재 사용할 수 있는 표현 |
|---|---|
| Kiln을 썼으니 모든 요청이 NPU다 | 지정 모델·대회 라우팅을 확인한 요청에 한해 근거 제시 |
| NPU니까 전력 X% 절감 | 토큰·호출·지연은 실측하고 전력은 측정 여부와 범위를 별도 표시 |
| 온체인이므로 내용이 모두 진실이다 | 보관한 승인·견적·실행 기록의 연결과 변경 여부를 검증 |
| 중지 버튼이 이미 제출한 결제도 취소한다 | 새 실행을 막고, 이미 제출된 거래와 revoke의 체인 순서를 추적 |
| 새로운 보안 증명/세계 최초 | 명시된 위협·테스트에서 관측한 통제와 검증 결과 |
