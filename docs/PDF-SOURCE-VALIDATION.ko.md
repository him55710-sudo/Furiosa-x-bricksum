# 정답표 없는 제한된 PDF 검수

2026-09-29. 새 PDF 검수 모듈을 현재 에스크로 엔진·감사 경로에 통합했다. 이 문서는 **로컬 개발 검증**을 설명한다. 기존 공개 Sepolia 거래의 전사 표 입력을 소급해서 raw PDF 처리라고 바꾸지 않는다.

## 무엇이 달라졌나

승인에는 문서 ID와 정책 해시가 포함된다. 정책은 원본 SHA-256, 페이지, 회사, 연도, 지표, 단위, 샘플 크기를 고정한다. PyMuPDF가 원본 바이트의 단어 좌표를 읽고, 제한된 표 문법이 연도·분기·행·셀을 대응시킨다. 납품의 수치, 원문 부호, 양수로 바꾼 지출액, 출처와 셀 ID를 모두 비교한다. 운영 코드에 분기별 정답값을 추가하지 않는다.

원본이 없거나 지원하지 않는 형식이면 **예치 서명 전에 중단**하며 `SOURCE_NOT_VERIFIABLE`과 세부 원인을 기록한다. 예치 이후 도구 장애가 발생한 경우 지급을 추정하지 않으며 기존 만료 환불 경로가 남는다. 감사자가 원본 또는 PDF 실행 환경을 갖추지 못하면 `INCOMPLETE`, 납품/기록이 어긋나면 `INVALID`다. 정상 검증 결과는 원문 자체의 진실성을 보증하지 않는다.

실패한 공급자는 한 분기의 샘플로 다음 예치 조건을 충족할 수 있다. 최종 지급에는 여전히 네 분기가 필요하다. 샘플 검증 버전으로 최종 납품을 승인할 수 없다. 기존 구매자 직접 환불과 감사 schema 3 경로는 유지된다.

## 관찰한 범위

| 입력 | 결과 |
|---|---|
| LGES 2025 Q4 자료, 2025년 | 네 분기 셀 대응 |
| LGES 2026 Q1 자료, 2025년 | 네 분기 셀 대응 |
| LGES 2026 Q2 자료, 2025년 | 네 분기 셀 대응 |
| LGES 2024 Q4 자료, 2024년 | `UNSUPPORTED_SOURCE_TABLE` |
| LGES 2025 Q2 자료, 2024년 | `UNSUPPORTED_SOURCE_TABLE` |

모두 이미 개발 과정에서 살펴본 동일 발행사 문서다. **3/5를 모델 정확도, 고객 성공률 또는 보류 평가 성공률로 쓰지 않는다.** 원본과 검수 규칙을 고정한 다음 제3자가 고른 미사용 문서로 별도 평가해야 한다. 사람의 원문 검토는 미완료다.

로컬 EVM 검증은 잘못된 값 환불, 한 행 샘플 이후 불완전한 최종 납품 환불, 정상 네 행 지급, 저장 영수증 재계산, PDF 실행 환경 부재, 미지원 문서의 예치 전 차단을 확인한다. [실행 결과](../artifacts/deal-escrow/source-documents/verification.json)에는 문서별 실패도 보존한다. 기본 테스트는 합성 좌표로 경계 조건을 검사하며 PDF와 Python 없이 실행된다. 실제 PDF 통합 시험은 아래 별도 명령으로 실행하고, 원본이 없으면 실패한다. 조용히 건너뛰지 않는다.

## 재현

Python 환경에 `requirements-pdf.txt`를 설치하고 필요하면 `ADE_PYTHON`을 해당 실행 파일로 설정한다. PyMuPDF 버전은 `1.24.14`다. 다운로드 원본은 Git에서 제외하며 URL과 해시는 저장소의 승인 목록에 있다.

```sh
python -m pip install -r requirements-pdf.txt
pnpm ade:pdf:import lges-2025-pdf
pnpm ade:pdf:import lges-2024-pdf
pnpm ade:pdf:import lges-2026q1-pdf
pnpm ade:pdf:import lges-2025q2-pdf
pnpm ade:pdf:import lges-2026q2-pdf
pnpm ade:pdf:verify
```

두 미지원 문서의 import 명령은 원본 해시 확인·저장 후 표 검사에서 실패한다. 이는 예상한 개발 관찰이며, 검증 명령은 그 실패가 예치 전 중단으로 이어지는지도 확인한다. 다른 문서를 지원하려면 문서·행·기간·단위 정책과 파서를 검토해야 한다. 임의 URL 입력 기능은 없다.

## 제품 판단에 미치는 영향

이 경로는 코드만으로 결과를 만들 수 있어 추출 모델 호출이 0이다. 견적 의미 비교에 쓰는 Kiln과 구분한다. 이 검증에서는 새 Kiln 호출이나 공개 체인 거래를 하지 않았다. 이 결과로 NPU의 전력 절감률을 주장하지 않는다.

추출과 검수가 같은 파서를 사용한다. 따라서 수치 변조·잘못된 셀 인용을 차단해도 파서가 공통으로 잘못 읽는 경우는 독립적으로 검증하지 못한다. reader·grammar 파일 해시와 파서 버전을 영수증에 남겨 재검증 환경 차이를 드러낸다.

무엇보다 무료 로컬 코드로 끝나는 의뢰에 유료 외주를 붙일 이유는 입증되지 않았다. 금융 통제 데모는 이 작은 표로 유지하되, 실제 파일럿은 **기존 외주 업무·오납품 원자료·공급자 동의·총비용 이점**이 확인된 한 건에서만 진행한다.
