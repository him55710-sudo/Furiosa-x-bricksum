# accord lock · 3분 시연

로컬 시연: [3분 스토리 데모](http://127.0.0.1:3440/#demo). `pnpm ade:spending:view`로 실행하고 하단 **시연 시작**을 누른다. 첫 진입은 정지 상태다. 녹화 영상이 아니라 공개 실행 기록을 순서대로 보여주는 인터랙티브 시연이다.

## 관객이 가져갈 한 문장

**AI가 외부 작업을 구매할 때, 구매자의 지출 한도를 지키고 블록체인에 대금을 잠근 뒤 정산하는 도구입니다.**

## 180초 진행표와 발표 대본

| 00:20–00:45 | 지갑, 구매자가 서명한 권한, 예산 계약, 초과 요청 차단 | 누가 얼마까지 허용했는지 |

| 01:30–02:05 | 판매자 B의 납품 실패 → 환불 → 다음 거래의 샘플 검증 | 실패가 다음 지출 조건으로 바뀌는 과정 |

**00:00–00:20**

“AI가 다른 AI에게 일을 맡기고 돈을 쓰게 된다면, 그 지출은 누가 통제할까요? 여기서는 PDF의 설비투자 데이터를 출처가 있는 표로 구매합니다. 빨간 소비 에이전트가 의뢰하고, 파란 판매 에이전트가 작업합니다. accord lock은 이 거래의 지출과 정산을 관리합니다.”

**00:20–00:45**

“돈의 권한은 구매자에게 있습니다. 구매자는 예산을 직접 넣고, 총 배정 한도와 건당 한도를 서명합니다. 이번 기록은 총 300, 건당 200 gwei입니다. AI가 구매를 제안하더라도 이 범위를 넘을 수 없습니다. 실제 201 gwei 요청은 예치 서명 전에 차단됐습니다. 계약도 별도로 한도를 강제합니다.”

**00:45–01:30**

“정상 거래를 보겠습니다. 소비 에이전트가 필요한 작업과 가격을 제안하면 정책이 구매 권한을 확인합니다. 통과하면 180 gwei를 스마트 계약에 잠급니다. 이제 판매자가 데이터를 전달합니다. 위쪽은 작업과 검수의 흐름, 아래쪽은 실제 돈의 흐름입니다. 신뢰하는 검수자가 원문과 납품 조건을 확인하고, 컨트롤러가 정산을 요청하면 계약이 판매자에게 지급합니다. 하단 링크에서 실제 예치와 지급 기록을 확인할 수 있습니다. 데이터가 맞는지 판단하는 일은 오프체인 검수자의 역할입니다.”

**01:30–02:05**

“다른 판매자가 잘못된 결과를 보내면 어떻게 될까요? 판매자 B의 납품은 검수에서 실패했고, 30 gwei가 환불됐습니다. 그리고 그 실패가 다음 거래의 조건이 됩니다. 같은 판매자에게 다시 구매할 때는 샘플을 먼저 확인해야 합니다. 샘플 없이 바로 예치하려는 요청은 막고, 확인을 통과하면 새 거래를 시작합니다. 전체 납품은 다시 별도로 검수합니다.”

**02:05–02:35**

“블록체인을 사용하는 이유는 앱이 꺼진 상황에서 더 분명해집니다. 실제로 앱을 종료한 뒤 계약의 기한이 지나자, 구매자는 별도 도구로 직접 환불을 요청했습니다. 앱이나 컨트롤러 키 없이 계약에서 30 gwei의 원금을 회수했습니다. 자동 환불은 아닙니다. 구매자가 직접 요청하고 가스 비용을 냅니다.”

**02:35–03:00**

“AI는 무엇을 살지 제안하고, 정책과 검수는 권한과 결과를 확인하며, 블록체인은 자금을 잠그고 지급하거나 환불합니다. 현재 컨트롤러와 검수자는 신뢰 대상입니다. accord lock은 에이전트의 구매 권한과 돈이 움직이는 조건을 명확하게 보여줍니다.”

## 발표 조작

- **Space**: 재생·정지. **← / →**: 이전·다음 장면. **Esc**: 시연 종료. 입력이나 버튼에 포커스가 있으면 해당 컨트롤의 기본 키 조작을 우선한다.
- 상단 장면 버튼과 하단 위치 슬라이더로 바로 이동한다. 슬라이더를 움직이면 일시정지한다.
- 증거 링크 또는 영수증을 열면 재생을 멈춘다. 다른 탭으로 전환할 때도 정지한다. 돌아온 뒤 **계속 재생**한다.
- 03:00에 마지막 장면에서 정지한다. **다시 시작**은 처음부터 재생한다.
- 발표에서는 첫 20초에 기술 용어보다 실제 구매 상황을 먼저 설명한다. 거래 링크 확인과 상세 영수증 탐색은 질문 시간에 하면 3분 흐름을 유지하기 쉽다.

## UX 점검으로 바꾼 부분

기존 3분 경로는 여러 운영 화면을 이동해 관객이 구매 상황과 자금 흐름을 동시에 따라가기 어려웠다. 여섯 장면의 한 화면 시연으로 바꾸고, 문서·지갑·서명·계약·꺼진 앱을 일러스트로 연결했다. 소비자는 레드, 판매자는 코발트 블루로 고정하고 역할 이름도 함께 표시한다.

블록체인을 단순한 잠금 아이콘으로 표현하던 부분에 실제 예치·지급·환불 링크와 계약 상태를 추가했다. 작업 전달과 검수를 위쪽, 자금 이동을 아래쪽에 배치해 책임을 구분한다. 한도 초과는 예치 전 차단이며, 그 금액이 예산 계약에 들어간 것처럼 보이지 않게 수정했다.

시연은 기존 Sepolia 기록을 압축 재생한다. 거래 상대는 모의 역할이고, 말풍선·문서 그래픽은 설명용이다. 문서 그림의 막대는 실제 투자금액 차트가 아니다. 새 거래를 실행하지 않으며 실시간 블록 확인으로 표시하지 않는다. 검수 정확성이나 무신뢰 정산, 판매자 지급 보장, 자동 환불을 주장하지 않는다.

이 점검은 화면·기능에 대한 설계 검토다. 처음 보는 실제 관객의 이해도는 별도 검증이 필요하다. 후속 관찰에서는 ‘누가 무엇을 구매하는가’, ‘돈은 언제 이동하는가’, ‘앱이 꺼지면 누가 회수하는가’를 관객이 스스로 설명할 수 있는지 확인한다.
