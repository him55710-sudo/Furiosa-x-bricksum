## 검사하는 경계

- 대화상 동의만 있는 경우, 다른 거래 해시, 다른 세션 서명, 다른 키의 서명을 거절한다.
- 새 메시지나 가격 변경 뒤에는 이전 버전 확인으로 commit할 수 없다.
- 없는 문장, 타 메시지 근거, 모호한 숫자, 분기 실적과 연간 전망 충돌을 차단한다.
- 첫 요청의 사람 예산을 제안 가격으로 처리할 수 없다. 가격·시간 변환은 원문의 유일한 금액·기간에서 코드가 수행한다.
- 양측 합의가 있어도 거래당 상한을 넘거나 과거 실패의 preview 조건이 없으면 funding operation과 nonce가 증가하지 않는다.
- 기존 accept API를 통한 협상 필수 mandate 우회도 막는다.
- 정상 납품 지급, 통제된 오납품 환불, 다음 거래 제한과 영수증 재검증을 실행한다.
- 메시지와 감사 이력을 고치면 검증이 실패한다. SQL update/delete도 불변 trigger로 거절한다.

[중지 API 관측](../artifacts/dealtrace/ui/stop-api.json)은 0회 추론·0건 정산으로 `HUMAN_STOPPED`를 남겼다. 이미 제출된 거래를 취소한다는 의미는 아니며, 그런 거래는 체인 상태를 재확인해야 한다.

## 측정의 해석

API 응답의 모델 ID, request ID, 흐름, 입력/출력 토큰, 지연, prompt hash를 저장한다. 반복 거래 차단·서명 검증·정산은 추론 없이 코드로 처리한다. 동일한 구매 요청과 구조화된 승인을 반복해서 모델에게 읽히지 않는다.

하드웨어 소비전력은 측정하지 않았다. 전력 계산을 추가할 경우 `API 지연 합계(초) × 요청에 배분한 가정 전력(W) / 3600`의 민감도 분석일 뿐이다. API 지연에는 큐·네트워크가 포함되고 요청별 서버 배분, 유휴 전력, PUE, 로컬 검증, 블록체인 노드 전력이 알려져 있지 않아 서비스 실측 Wh 또는 NPU/GPU 절감률이라고 부를 수 없다.

[최종 흐름별 계측과 가정 계산](../artifacts/dealtrace/efficiency.json)에서 API 지연 합계는 60.225초다. 가정 전력이 25 / 50 / 100W라면 계산값은 약 0.418 / 0.836 / 1.673Wh다. 전력 수치를 측정한 것처럼 표시하지 않으며, 전력 절감률 비교에도 사용하지 않는다.

## 아직 주장하지 않는 것

외부 조직의 독립 Agent 인증, 미관측 대화의 정확도, 실제 사용자의 감사 이해도, 유료 고객 수요, 물리 NPU 경로·전력 계측, 당시 새 DealTrace 공개 테스트넷 실행은 남아 있었다. 현재 결과는 위 최신 실행과 별도 공개 실증 문서를 따른다. 수수료는 기존 구조처럼 별도 운영자 가스 예산이며 DEMO 구매 원금 상한과 합쳐진 단일 금액 상한이 아니다. 검수는 고정된 원문 참조 프로필에 의존한다. 운영자 신뢰를 제거하는 분쟁 판정 시스템은 아니다.

이 제품의 주장은 모든 자연어 협상을 이해한다는 것이 아니라, **이 좁은 업무에서 의미 해석의 후보와 실제 금융 권한을 분리하고, 근거와 결과를 다음 지출 제한까지 연결했다**는 것이다.


### 저장소 줄바꿈과 원본 재현

공개 실행 당시 코드와 최초 118/118 검사 지문은 `d3e632ff4cbaaf954ddd680ccba23dfc95a1b463a2df630fe3220664f623688e`로 같았다. Git에 올리기 전 다섯 소스 파일의 Windows CRLF만 저장소 규칙인 LF로 바꾸고 118개 검사를 다시 실행했다. [정규화 기록](../artifacts/dealtrace/runs/7d2a57a8-f236-46a8-b9da-198de969cf6e/source-normalization.json)은 원본·정규화 해시와 원본 파일 위치를 연결한다. 코드 내용과 동작 변경은 없다. 원실행의 엄격한 byte 지문으로 resume하려면 보존된 다섯 원본을 별도 checkout에 복원해야 한다. 일반 새 실행은 현재 LF 소스를 그대로 사용한다. 현재 검사 지문은 tests.json에 별도로 기록한다.
