# 초면 사용자 3명 이해도 검증

상태: **미실시. 실제 응답 0명.** 구현과 자동 화면 검증을 사람의 평가로 세지 않는다.

서로 답을 공유하지 않은 초면 참가자 세 명에게 https://agent-spending-firewall.vercel.app/ 의 샘플과 Evidence library를 보여준다. 브라우저는 예산 40 / 거래당 한도 30 / 합의 20 / 청구 25이며, 공개 증거는 run `fa5e107c-7a20-4a6d-9970-5f15e8d4f6e9`이다. 그록봇의 체험 후기는 AI 사전 검토이며 인간 응답으로 집계하지 않는다. 진행자는 시연을 보여주기 전에 정답을 설명하지 않는다. 참가자의 신원이나 연락처는 수집할 필요가 없다.

기록만 읽고 아래 세 질문에 자유롭게 답하도록 한다. 정답이나 합성 대본을 먼저 보여주지 않는다.

1. 사용자는 얼마까지 지출을 허용했는가?
2. 예산 40인데 판매자의 청구 25는 왜 막혔는가?
3. 최종 지급 20은 왜 허용됐는가? 근거로 사용한 기록은 무엇인가?

추가로 기록 화면을 2분 동안 탐색하게 한 뒤, 원 메시지·확정 거래·납품·청구·실제 거래 중 어떤 기록을 근거로 삼았는지 묻는다. 찾지 못한 항목과 이해하지 못한 표현도 그대로 적는다. 이 후속 확인을 시연 직후 응답과 섞지 않는다.

익명 기록 양식:

```text
참가자: P1 / P2 / P3
일시:
기존 프로젝트 설명을 들은 적: 예 / 아니오
본 버전: Accord Lock / 공개 run fa5e107c
방문 URL 및 배포 버전:
질문 1 원문 응답:
질문 2 원문 응답:
질문 3 원문 응답:
기록 탐색 후 근거로 지목한 항목:
막힌 부분 / 받은 도움:
```

평가는 원문을 보존한 뒤 별도 열에 적는다. 대상 사용자·업무를 짚었는지, 예산과 합의 금액을 구분했는지, 양측 확인·인간 권한·납품 검수·일치하는 청구가 지급 근거임을 이해했는지를 각각 확인한다. 세 명이 모두 핵심 이유를 재구성하지 못하면 UI나 설명을 수정하고 새 버전으로 다시 확인한다. 세 명의 성공도 시장 수요나 일반적 사용성의 증거로 확대하지 않는다.

제공된 [3개 합성 대본](ACCORD-SYNTHETIC-REVIEWERS.en.md)은 발표 설명용이다. 원본의 Seller C는 대표 공개 기록의 Seller A와 다르며, 실제 참가자 응답으로 집계하지 않는다.
