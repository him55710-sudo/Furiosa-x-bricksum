2026-09-28 / **PLANNED**. [기획 v2](HACKATHON-PLAN.ko.md)의 목표다. 지금 실행 가능한 시연은 [기존 실행서](DEMO-RUNBOOK.ko.md)를 따른다. 공개 체인·문서 결과·직접 취소·독립 브라우저 검증 화면은 구현 전이다.

## 관객이 기억할 문장

“문서 100장을 처리하라고 맡겼지만 수수료까지 8 이상은 허락하지 않았습니다. 12 청구는 막았고, 6으로 끝낸 작업은 받은 파일과 승인 근거를 함께 확인할 수 있습니다.”

TC는 테스트 포인트라고 항상 표시한다. 원화·상용 카드 결제처럼 꾸미지 않는다. NPU·서명·tx·B0/B1/CM은 결과를 본 뒤 상세로 연다.

## 4분 장면

| 시간 | 조작 | 화면에서 보여줄 사실 | 남은 구현 |
|---|---|---|---|
| 0:00–0:30 | 공개 합성 PDF의 CSV 변환 요청. 조건 확인·서명 | 총 20 / 건별 8 / A·B / 기한 / 테스트 가스 지원. 사람의 승인 | job spec·입력/출력 |

시간은 대본 목표이며 모델/네트워크 지연 보장이 아니다. 긴 협상은 보조 영상으로 둔다. live가 지연되면 진행 중·취소 가능 상태를 보인다. 저장한 실제 실행으로 전환하면 **‘기록 재생’**을 표시한다. fixture를 Qwen 응답으로 바꾸어 부르지 않는다.

공개 체인의 finality 대기를 4분 안으로 약속하지 않는다. live 신규 거래는 ‘포함 확인 / 최종 확정 대기’를 그대로 표시한다. 확정된 독립 감사 장면은 리허설에서 끝난 동일 버전의 별도 run을 사용할 수 있지만 그 run ID와 ‘이전 실제 실행’을 명시한다. 신규 지급과 이전 확정 영수증을 같은 거래처럼 섞지 않는다. 전체 관통 실행의 완료 증거는 실제 finality 확인 뒤 따로 보관한다.

감정의 흐름은 ‘12를 써버릴까’ → ‘돈이 나가지 않았다’ → ‘정상 6 거래는 끝났다’ → ‘원 서버가 없어도 확인된다’다. 결과가 없는데 그래픽만 성공처럼 보여주지 않는다.

## 제출 화면

상단에는 한 작업: 입력 / 최대 총액 / 판매자 / 기한 / 상태. 중간은 `승인 → 제안·확정 견적 → 정책 판정 → 지급 → 결과 수령`. 오른쪽에는 지급액·남은 예산·AI 호출·영수증 버튼을 둔다.

| 상태 | 먼저 읽히는 문구 | 상세 |
|---|---|---|
| 초과 | “수수료를 포함하면 12입니다. 허용한 8을 넘어 결제하지 않았습니다.” | 사유·서명 견적·chain state |
| 반복 차단 | “총액을 먼저 확인했습니다. 이번에는 AI를 호출하지 않았습니다.” | control source·scope·usage |
| 지급 후 대기 | “6을 지급했습니다. 결과 파일을 기다리고 있습니다.” | 지급과 제공 상태 구분 |
| 완료 | “변환 결과를 받았습니다. 지급액은 승인 범위 안입니다.” | 검사 범위·tx·영수증 |
| 취소 미확정 | “새 요청을 중지했습니다. 체인의 권한 취소는 확인 중입니다.” | 이미 제출된 지급은 별도 추적 |
| 감사 | “이 결제는 서명된 승인 범위 안에 있습니다.” | 관측 블록·검증/미검증 항목 |
| 변조 / 누락 | “기록이 일치하지 않습니다.” / “자료가 없어 판단할 수 없습니다.” | INVALID / INCOMPLETE |

하나의 ‘블록체인 검증 완료’ 배지에 모든 보장을 섞지 않는다. **승인 준수 / 자금 이동 / 파일 일치 / 품질 검사**를 구분한다. hash 일치만으로 변환 정확도 100%라고 쓰지 않는다.

## 처음 보는 사람에게 확인

아직 실행하지 않은 사용성 실험이다. 아래 수치는 관측값이 아니라 첫 통과 목표다. 역할이 다른 3명에게 설명 없이 작업·기록을 준다.

1. 15초 후: 누가 무엇을 맡겼고, 최대 얼마까지 허용했는가?
2. 차단 화면: 왜 돈이 나가지 않았으며, 중지는 오작동인가?
3. 결과 화면: 결제만 됐는가, 파일도 받았는가?
4. JSON만 받은 감사자: 60초 내에 허용액·실제액·판매자·기한·결과 존재를 찾고 승인 준수를 설명한다.
5. 서버 종료·변조·누락: 원본/변조본/누락본 판정을 구별한다. 체인이 상품 품질까지 보장한다고 오해하면 설명을 고친다.

3명 모두 핵심 한도와 상태를 맞히는 것을 첫 목표로 둔다. 실제 시간·오답·도움 요청을 기록한다. 작은 표본 통과는 시장 검증이나 일반 사용성 입증이 아니다.

## 주장과 제출 자료

‘모든 에이전트 안전’, ‘즉시 응답’, ‘NPU 전력 X% 절감’, ‘납품/환불 분쟁 자동 해결’은 현재 주장하지 않는다. 공개 tx와 독립 검증이 나오기 전에는 공개 실증 성공이라고 쓰지 않는다. Memory를 모델의 자가 학습이라고 소개하지 않는다.

완료한 commit, 모델 응답·flow usage, 승인·견적·지급·제공 기록, 독립 검증 결과, 공개 배포 정보, 정상/차단/중지의 tx 또는 결제 부재 관측을 묶는다. 제품의 단일 실행과 비교 실험은 구분한다. 영상은 합성 입력·테스트 자산으로 촬영하고 비밀 키를 담지 않는다.

새 기능이 준비되지 않으면 기존 3분 로컬 크레딧 데모를 사용한다. 목표 시연의 미구현 장면을 완성된 기능으로 발표하지 않는다.
