# AI의 추가 가치: 알려진 사례에서 규칙도 같은 결과를 냈다

2026-09-29. 기본 체크아웃의 기존 개발 비교 기록을 읽고, 원 관측치에서 집계 수치를 다시 계산해 요약과 일치함을 확인했다. 두 비교의 사례 바이트와 참조 자료 지문도 일치했다. [재집계 기록](../artifacts/deal-escrow/prior-comparison/reconciliation.json)에 원본 위치와 SHA-256, [AI 보고서](../artifacts/deal-escrow/prior-comparison/ai-report.json)와 [규칙 보고서](../artifacts/deal-escrow/prior-comparison/rules-report.json)의 스냅샷을 보존했다.

| 기존 실험의 방식 | 평가 횟수 | 의도한 결과 | 정상 납품 | 잘못된 지급 | 모델 호출 | 토큰 |
|---|---:|---:|---:|---:|---:|---:|
| 초기 규칙 | 16 | 10 | 8 | 0 | 0 | 0 |
| 강화한 규칙 | 16 | 16 | 12 | 0 | 0 | 0 |
| AI + 코드 | 16 | 16 | 12 | 0 | 18 | 22,072 |
| AI + 실패 이력 | 16 | 16 | 12 | 0 | 16 | 19,312 |

**이 자료는 AI의 우위를 입증하지 않는다.** 작성한 사례 8개를 2회씩 평가했고, 강화 규칙은 사례를 본 뒤 수정됐다. 두 방식의 실행 시점도 다르다. AI 결과는 재사용한 기록이며 이번에 새로 호출하지 않았다. 처음부터 알려지지 않은 문서·업무나 독립 사용자의 자료로 일반화할 수 없다.

기존 기본 체크아웃은 AI가 견적의 의미를 구조화해 검토하고 코드가 가격을 정렬하는 별도 구현을 사용했다. 현재 작업 브랜치의 `select_offer` 구현과도 다르다. 따라서 이 숫자를 현재 브랜치의 성능, 새 단위 문맥의 개선 효과, NPU 전력 절감률로 표시하지 않는다. 실제 체인 영수증 전체를 이 재집계에서 다시 검증한 것도 아니다.

제품 결정은 다음과 같다.

- 지원하는 PDF의 무료 로컬 추출 경로를 유지한다. 같은 결과를 코드로 얻을 수 있다면 모델을 필수로 끼워 넣지 않는다.
- Kiln의 실제 모델 호출과 안전한 결제 경계는 각각 입증하되, 지능의 추가 효용이나 GPU 대비 효율과 혼동하지 않는다.
- 새로운 모델·규칙 수정 전에 실제 후보 사용자의 미해결 주문을 동결한다. 성공한 납품, 실패·환불, 불필요한 거절, 비용과 사람의 시간을 함께 비교한다.
- 현재 정산·재의뢰 기술 실증이 고객 가치 검증을 대신하지 않는다. 알려진 사례를 더 복잡하게 꾸며 우위를 만들지 않는다.
