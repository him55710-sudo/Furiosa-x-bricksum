# 기획 기반 페르소나 검증

> 후속 보완: 현재 주제품인 Agent Deal Escrow의 품질 승인·구매 의도·배송·복구·감사를 [남은 한계 보완 기록](LIMITATIONS-REMEDIATION.ko.md)에 정리했습니다. 아래 실행 결과는 이전 Control Memory 구현의 역사적 기록입니다.

2026-09-28. 사용자의 요청에 따라 가상 상황을 맡은 세 검토 에이전트가 기획과 코드를 읽고 행동 시퀀스를 제안했습니다. 개발 리드/예산 책임자, 판매자/공격자, 장애 운영자/독립 감사자 관점입니다. 이 검토는 실제 고객 인터뷰나 구매 의사 관측이 아닙니다.

근거는 [개선 기획](HACKATHON-PLAN.ko.md), [실험 프로토콜](EXPERIMENT-PROTOCOL.ko.md), [아키텍처](ARCHITECTURE.ko.md)입니다. 제안에서 실행 가능한 행동을 `verification/persona-plan.mjs`와 `verification/personas.test.mjs`로 고정했습니다. 코드·서명·SQLite·로컬 EVM은 실제로 실행하고, 구매 에이전트의 선택과 판매자 응답은 합성 정책으로 제어합니다. 실제 Kiln 추론 비용은 발생시키지 않습니다.

```powershell
pnpm run verify:personas
# 한 상황만 재현
node scripts/verify-system.mjs --suite=personas --case=PER-008
# 기존 검증과 브라우저 회귀까지 포함
pnpm run verify:system
```

각 실행의 보고서는 `artifacts/verification/<run-id>/report.html`입니다. `evidence/persona-001.json` 등의 파일에 역할·목표·기획 근거·행동·run ID·승인·결제액·견적·호출·독립 검증 결과가 남습니다. 실패 시점까지의 관측도 보존합니다. `PASS`는 정의한 검사의 통과이며, 별도로 보고한 품질 저하·통제 마찰·증거 한계가 해결됐다는 뜻이 아닙니다.

## 첫 실행에서 확인한 문제

첫 실행 `2026-09-28T11-20-13-985Z-3b9d72db`는 4/10 통과였습니다. 오류를 통과 조건으로 바꾼 대신 다음 구현을 보완했습니다.

1. **후보별 부적격이 전체 구매를 중지:** 한 판매자만 승인한 9개 조합과 낮은 한도/혼재 후보 15개 조합이 모두 과잉 차단됐습니다. 부적격 후보를 기록 후 제외하고 적격 후보를 계속 비교하도록 변경했습니다. 모두 제외된 경우의 중지 사유는 유지합니다.
2. **조기 견적 거절 때문에 정상 대안도 차단:** B1/CM에서 정상 대안까지 REVIEW_REQUIRED가 됐습니다. 거절 후보만 제외하며, 대안이 없을 때 확인을 요구합니다. 견적 성공 수와 시도/거절 수를 별도로 기록합니다.
3. **UNKNOWN 이후 취소가 nonce를 소비해 영구 미확정:** 실제 receipt를 먼저 확인하고, 확정 블록의 nonce 증가와 해당 paymentKey 미사용을 함께 확인한 경우에만 `SUBMISSION_NONCE_CONSUMED`로 종료합니다. 이 확정 규칙은 로컬 devnet 대상이며 공개 체인의 reorg/finality 전략은 별도입니다.
4. **세션을 넘겨받은 통제의 원인 자료 누락:** export에 원본 승인·견적·이벤트를 추가하고, 소유자/목적/판매자 범위와 서명·체인 승인·정책의 내부 재현성을 확인합니다.
5. **변조한 현재 세션 요약도 설명 없이 VALID:** `observedSession`에 관측 블록의 체인 값을 반환하고 `unverifiedFields`로 mutable 요약을 구분합니다. 감사 UI에도 관측값과 미검증 설명을 표시합니다.

페르소나 검토 에이전트가 수정안을 다시 검토한 뒤, 완료/중지된 모든 관측에 독립 verifier `VALID`를 필수 단언하도록 검사를 강화했습니다. 의도한 UNKNOWN 관측은 INCOMPLETE이어야 합니다. 성공 견적 0건을 견적 시도 0회로 오해하지 않도록 실패 시도 계측도 추가했습니다.

## 해결됐다고 주장하지 않는 항목

- **품질 주입:** 공격 지시를 따르는 합성 선택기는 여전히 허용된 C를 선택할 수 있습니다. 정상 B보다 4 TC를 더 내고 20 credits와 환불 48시간을 잃습니다. 예산·목적·서명 제한의 통과가 구매 품질을 보장하지 않습니다. 실제 Kiln의 주입 성공률은 이번에 측정하지 않았습니다.
- **통제 마찰:** 확정 견적을 일찍 제공하지 않는 판매자만 있으면 B1/CM의 구매 성공이 B0보다 낮을 수 있습니다. 사람 개입 횟수나 시간을 임의 추정하지 않습니다.
- **구매 의도의 중복:** API 멱등성은 동일 requestId 기준입니다. 다른 탭이나 새로운 ID의 요청을 같은 구매 의도로 식별하는 기능은 없습니다.
- **증거의 사실성과 완전성:** 통제 원본 자료의 서명·scope·내부 재현성을 검증해도, 미앵커 실패 사건의 실제 발생/완전성과 당시 예약 잔액을 독립 증명한 것은 아닙니다. 이를 verifier와 UI의 미검증 범위로 명시합니다. 온체인 결제와 앵커 이후의 변경 검증은 별도입니다.
- **실제 사용자/운영 환경:** 합성 고객과 판매자는 실제 사용성 연구·수요 검증·실물 공급/환불 증거가 아닙니다. 테스트 자산·로컬 체인·단일 worker 범위입니다.
